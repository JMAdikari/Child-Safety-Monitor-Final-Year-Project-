## Project Overview

Phase 2 of a Montessori classroom child safety monitor. The system detects falls and climbing in real time using a camera feed. It is a **final year research project** — Phase 1 exists as a comparison baseline and must not be deleted.

**Working directory for all commands:** `montessori-safety/`

## Critical Environment Constraints (Windows)

### Venv location
The venv lives inside the project at `montessori-safety/venv/`:

```
python -m venv venv
venv\Scripts\activate
```

### Package conflict rules
- **Only `opencv-contrib-python`** — never install `opencv-python` alongside it. `rtmlib` needs `cv2.dnn` which only exists in the contrib build.
- **numpy must be `==1.26.4`** — `torch==2.2.0` and `ultralytics==8.3.0` break with numpy 2.x. If `opencv-contrib-python` upgrades numpy, immediately run: `pip install "numpy==1.26.4"`

### Common commands
```bash

# Install / sync dependencies
```

## Architecture

The pipeline is a linear chain. Each stage's output feeds the next:

```
Camera / Video
    │
    ▼
PersonDetector          src/detection/person_detector.py
(YOLO11n + ByteTrack)   → per-person bounding boxes + persistent track IDs
    │
    ▼
RTMPoseExtractor        src/pose/rtmpose_extractor.py
(rtmlib, ONNX, CPU)     → 17 COCO keypoints (x, y, conf) per person
                        → compute_features() returns:
                            feature_vector (51,)       ← fed to CNN-LSTM
                            activity_features dict     ← fed to rule detector
    │
    ├──► ActivityClassifier        src/classification/activity_classifier.py
    │    (1D CNN-LSTM)             15-frame sliding window per track_id
    │    loads child_cnn_lstm_best.pth
    │    outputs: normal / fall / climb + confidence
    │
    ├──► RuleBasedDetector         src/classification/rule_based_detector.py
    │    geometric safety net      fall: aspect_ratio + body_angle
    │                              climb: ankle elevation vs personal baseline
    │
    ├──► ZoneMonitor               src/zones/zone_monitor.py
    │    polygon geometry          leaving / danger_zone alerts
    │    config: configs/zones.json
    │
    ▼
AlertSystem             src/alerts/alert_system.py
                        winsound.Beep(1000, 500)  ← Windows alarm
                        WebSocket → dashboard
                        Twilio SMS (optional)
```

**Main pipeline (post-training):** `src/pipeline/main_pipeline.py` — not yet created, pending model training.

## Phase 2 Model

| Property | Value |
|---|---|
| Architecture | Conv1d(51→64→128) → LSTM(128→128, 2L) → FC(128→64→3) |
| Input shape | `(batch, 15, 51)` — 15 frames × 51 features |
| Output | 3 classes: `0=normal, 1=fall, 2=climb` |
| Model file | `models/saved/child_cnn_lstm_best.pth` |
| Training script | `src/classification/train_cnn_lstm.py` (run on Google Colab T4) |
| Phase 1 backup | `models/saved/activity_lstm_best.pth` — keep for dissertation comparison |

The `CNNLSTMClassifier` class defined in `train_cnn_lstm.py` is imported by `activity_classifier.py` at runtime. Both must stay in sync.

## Data Pipeline (current stage — pre-training)

```
Record videos
    │
    ▼
python preprocess_videos.py --check "path/to/video.mp4"
    │
    ▼
python track_viewer.py --video "path/to/video.mp4"
(note which track_id performs each dangerous activity)
    │
    ▼
Edit data/child_datasets/self_recorded/ground_truth.csv
    │
    ▼
python src/pose/extract_child_poses.py --all
    │   Outputs: data/processed/child_pose_sequences/
    │   all_train_sequences.npy  shape (N, 15, 51)
    │   all_train_labels.npy     shape (N,)  — 0/1/2 only
    │
    ▼
python verify_data.py           ← check shapes, NaN, class counts
    │
    ▼
python augment_skeleton_data.py ← if fall/climb class < 50 sequences
    │
    ▼
Upload .npy files + train_cnn_lstm.py to Google Drive → train on Colab T4
    │
    ▼
Download child_cnn_lstm_best.pth → models/saved/
```

**Important:** `leaving` is NOT a CNN-LSTM class. It is handled by `ZoneMonitor` geometry. The `LABEL_MAP` in `extract_child_poses.py` only has `{normal:0, fall:1, climb:2}`. Do not add `leaving` back.

## Key Invariants

- All scripts import using `src.` prefix and expect to be run from `montessori-safety/` (not from inside `src/`).
- `RTMPoseExtractor.compute_features()` always returns a `(51,)` vector — if `valid_keypoints < 4` the vector is still 51 zeros. Callers must check `valid_keypoints` before classifying.
- `ActivityClassifier` returns `None` for the first 14 frames of any new `track_id` (buffer filling). Callers must null-check.
- `RuleBasedDetector` needs ~30 frames to establish the ankle baseline before `detect_climb()` is meaningful.
- Zone config is saved/loaded from `configs/zones.json` via `ZoneMonitor.save_config()` / `load_config()`.
- Alert cooldown per `(track_id, activity)` pair is 10 seconds — set in `AlertSystem.__init__`.
